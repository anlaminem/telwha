Short Strategy on Bybit Listings: Testing TP/SL and Entry Time

A case study on a short strategy simulator for new Bybit listings: how to test an idea through historical candles, grid search, and time-based patterns instead of a very confident “it seems right to me.”

A new contract appears on the exchange, the first minutes fly in every direction, and then some participants remember risk management. This short “post-listing” window became the focus of this case.

The task looked standard for any product with market logic: formalize the hypothesis, collect the data, build the simulator, run the parameters, and see whether a stable edge exists. In this case, specifically, it meant short trades on confirmed Bybit listing events with fixed risk and clear TP/SL logic.

If a strategy does not pass a simple backtest, it has no chance of surviving in an environment where decisions are made at product speed, not presentation speed.

For the test, I used ten confirmed listing events of USDT contracts. For each launch, a minute-level data window was loaded: from 18 hours before the listing to 10 hours after. At this stage, the pre-listing segment is kept as context for future pattern analysis, while the post-listing segment is used directly in the trade simulation. The data came through the Bybit V5 Market Kline endpoint, which returns historical candles for a given symbol, interval, and time range.

The listing moment is defined as entry_dt, and the data frame is defined by start_dt and end_dt. As a result, the model contains proper context before the event and a full cut of the period after it.

The candle retrieval function converts timestamps to milliseconds, sends the API request, and returns an ordered DataFrame. No “synthetic” data, only what exists in the instrument’s history.

Code Retrieving historical kline data ▾ 
def get_klines(symbol, start_dt, end_dt, category="linear", interval="1"):
    start_ts = int(start_dt.timestamp() * 1000)
    end_ts = int(end_dt.timestamp() * 1000)

    resp = session.get_kline(
        category=category,
        symbol=symbol,
        interval=interval,
        start=start_ts,
        end=end_ts,
        limit=1000
    )

    rows = resp["result"]["list"]
    df = pd.DataFrame(
        rows,
        columns=["timestamp", "open", "high", "low", "close", "volume", "turnover"]
    )
    df["datetime"] = pd.to_datetime(df["timestamp"].astype("int64"), unit="ms", utc=True)
    return df.sort_values("datetime").reset_index(drop=True)

Next comes the trade simulator. Entry starts from the first candle not earlier than entry_dt, and then TP, SL, and timeout are checked in sequence.

The scheme is intentionally minimalist: one entry point, fixed risk size, and a linear candle-by-candle scan until TP/SL is triggered or the scenario ends. This framework makes the result quick to interpret and avoids hiding the logic under layers of complexity.

Code Basic short trade simulation ▾ 
def simulate_short_trade(df, entry_dt, entry_amount=100.0,
                         tp_pct=5.0, sl_pct=4.0, duration_min=600):
    mask = df["datetime"] >= entry_dt
    if not mask.any():
        return None

    entry_idx = mask.idxmax()
    entry_price = float(df.loc[entry_idx, "close"])
    pos_qty = entry_amount / entry_price

    tp_price = entry_price * (1 - tp_pct / 100.0)
    sl_price = entry_price * (1 + sl_pct / 100.0)
    end_idx = min(entry_idx + duration_min, len(df) - 1)

    for i in range(entry_idx + 1, end_idx + 1):
        high_i = float(df.loc[i, "high"])
        low_i = float(df.loc[i, "low"])

        if low_i <= tp_price:
            return {"PnL": (entry_price - tp_price) * pos_qty,
                    "closure_type": "TP"}
        if high_i >= sl_price:
            return {"PnL": (entry_price - sl_price) * pos_qty,
                    "closure_type": "STOP"}

    last_close = float(df.loc[end_idx, "close"])
    return {"PnL": (entry_price - last_close) * pos_qty,
            "closure_type": "TIMEOUT"}

On top of this base, an extended version was added with multiple TP levels, partial exits, and averaging. Where a product needs more flexible position management logic, these are the blocks that change first.

The next layer is parameter selection. Instead of arguing whether TP 5% “sounds more solid” than 4%, a grid search was run: several options for the first and second TP, several stop-loss levels, and several position allocation structures, including full exit and split scenarios.

This is a standard approach for any backtest module: define a parameter grid, run it on the same sample, and only then evaluate what makes sense to move into production.

If the product needs an “experiment mode,” this is the most convenient place to connect alternative parameter grids and compare them on new batches of listings.

On the sample of 10 listings, the best result came from a simple setup: TP levels = [5, 6, 12], TP shares = [1.0, 0.0, 0.0], stop loss = 4%. In other words, a full exit at the first TP proved more effective than any split structure.

The final figures for this configuration were: total result 14.95 USD with fixed risk of 100 USD per trade, mean result 1.50 USD per trade, win rate 60%, and closure structure of 6 TP, 4 SL, and 0 timeout. For a small sample, these are modest values, but they are enough to distinguish a viable hypothesis from a purely emotional one.

Entry timing was also calculated separately. The weakest window in this sample was 04:00 UTC, while the most consistently positive one was 06:00 UTC. For a product, this gives a simple but useful signal: time is a valid candidate for an additional risk filter, not just a decorative parameter.

What this gives the product

From a solution architecture perspective, the result can be described as follows: the base short logic works with TP 5% and SL 4%, a full exit at the first TP, and a time filter that favors 06:00 UTC while encouraging more caution around 04:00 UTC. This is a transparent rule set that is easy to transfer into a product, monitor on a broader sample, and adapt to a different universe of instruments when needed.

For teams building their own strategies or market services, not only the specific setup matters but also the method itself: a clearly stated hypothesis, an explicit link to exchange data, a backtest with a controlled parameter grid, and readable output metrics. In this structure, the instruments, horizons, and universe can change, while the validation mechanics remain stable.

  • Foundation: a short simulator based on Bybit historical candles with proper TP/SL control.
  • Conclusion: a simple full exit at TP1 showed better behavior than split exits on the test set of listings.
Formal hypothesis testing does not guarantee a perfect strategy. It guarantees one thing: you stop paying the market for decisions that could have been filtered out at the notebook stage.
